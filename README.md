# Путевик

Прототип приложения для маршрутов по местам и объектам: строите маршрут из
контрольных точек, идёте по нему, приложение засекает прохождение по GPS
и помнит прогресс между запусками. Работает офлайн, ставится на домашний экран.

Живая версия: **https://dictordozel.github.io/putevik/**

---

## Как запустить локально

`file://` не подойдёт: браузер запрещает ES-модули с локального файла, а геолокация
и Service Worker требуют защищённого контекста. `localhost` считается защищённым,
поэтому достаточно поднять простой сервер:

```bash
cd путь/к/проекту
python -m http.server 8000
```

Затем откройте `http://localhost:8000/`.

> **Если на Windows `python` падает с «The system cannot find the path specified»** —
> это сломанный ярлык-псевдоним Microsoft Store в `%LOCALAPPDATA%\Microsoft\WindowsApps`,
> а не отсутствие Python. Штатный лончер при этом работает:
> `py -m http.server 8000`.

## Как проверить с телефона

GitHub Pages отдаёт сайт по HTTPS — только так мобильный Chrome даёт доступ
к GPS и разрешает установку приложения.

1. Откройте `https://dictordozel.github.io/putevik/`.
2. Разрешите доступ к геопозиции.
3. Меню браузера → «Добавить на главный экран» — появится иконка, запуск без адресной строки.
4. Постройте маршрут во дворе (радиус точек лучше поставить 20–30 м) и пройдите его.

Для проверки офлайна: включите авиарежим и запустите приложение с иконки —
маршрут, прогресс и ранее просмотренные участки карты останутся на месте.

```

```

## Модель данных

Места хранятся отдельно от маршрутов, маршрут ссылается на них по id,
а прогресс лежит отдельно по каждому маршруту — поэтому одно место,
попавшее в два маршрута, не «проходится» в обоих сразу.

```js
localStorage['putevik.v1'] = {
  version: 1,
  places:  { pl_xxx: { id, name, note, kind, lat, lng, radius, createdAt } },
  routes:  [ { id, name, placeIds: [...], createdAt, updatedAt } ],
  activeRouteId,
  progress: { rt_xxx: { completedIds: [...], startedAt, lastAt } },
  settings: { simulate, autoFollow, defaultRadius }
}
```

Статус точки (`🔒 Заблокировано` / `➜ Следующая цель` / `✓ Пройдено 🎉`) нигде
не хранится — он вычисляется из `completedIds` и позиции точки в порядке маршрута.

Битый JSON в хранилище не роняет приложение: копия уезжает в
`putevik.v1.broken.<время>`, работа продолжается с чистого состояния.

## Как засчитывается прохождение

Точка считается пройденной, когда выполнены три условия:

1. это следующая по порядку непройденная точка;
2. расстояние до неё не больше её радиуса;
3. погрешность фикса не больше `max(30 м, радиус точки)`.

Третий пункт — не придирка. Позиция по Wi-Fi легко приходит с погрешностью
±500 м, и без этого фильтра маршрут «проходился» бы целиком, не сходя с места.
Плюс требуются два подряд подходящих фикса, иначе статус мигает на границе зоны.

## Состояния GPS

| Индикатор | Что значит |
|---|---|
| `GPS активен` | свежие фиксы приходят |
| `Ищем спутники…` | запрос отправлен, ответа пока нет |
| `Ждём сигнал…` | таймаут одного запроса, слежение продолжается |
| `Сигнал потерян` | больше 20 с без нового фикса (туннель, помещение) |
| `Нет доступа` | пользователь запретил геолокацию |
| `Нужен HTTPS` | открыто по `http://` — браузер не отдаст позицию |
| `Симуляция` | позиция задаётся вручную |

## Режим симуляции

Панель → «Отладка» → «Режим симуляции GPS». Нужен, чтобы проверять прохождение
маршрута на десктопе, где настоящий GPS отдаёт одну неподвижную неточную точку.

- перетаскивание синего маркера мышью — телепорт;
- стрелки клавиатуры — шаг 10 м, с Shift — 50 м;
- «Идти по маршруту» — автопроход со скоростью 5 км/ч.

Симуляция отдаёт наружу такие же фиксы, как настоящий GPS, поэтому проверяется
именно тот код, который потом работает на телефоне.

## Офлайн

Тайлы карты и векторные слои независимы: при обрыве сети подложка гаснет
и появляется предупреждение, но точки, круги радиусов, линии маршрута
и расчёт расстояний продолжают работать.

Service Worker использует две стратегии осознанно:

- **свои файлы — network-first**: при живой сети всегда свежий код. Иначе прототип
  попадает в классическую ловушку, когда правки «не видны» из-за старого кэша;
- **тайлы — cache-first** с фоновым обновлением, лимит 600 плиток.

## Что пока не сделано

- Маршрут между точками рисуется прямой линией — прокладка по дорогам требует
  внешнего роутинг-сервиса.
- Обмен маршрутами — через «Экспорт JSON» / «Импорт JSON». Ссылки-шеринга нет.
- У места есть название, заметка, тип и радиус; фото и произвольных полей нет.

## Проверка логики

Ядро (расстояния и состояние маршрута) не зависит от браузера, поэтому его
можно прогнать в Node. Тесты лежат вне репозитория — см. историю разработки;
проверялись построение маршрута, порядок статусов, изоляция прогресса между
маршрутами, сборка мусора в справочнике мест, экспорт/импорт и восстановление
после битых данных.
